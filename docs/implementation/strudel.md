# Strudel (#18)

The model has two engines. The **built-in synth** is its own voice (Self, Attuned or Jukebox). **Strudel** is live-coded music as on strudel.cc, **listener modes only (Attuned and Jukebox)**, switched on and off with the tool `strudel_mode`. Decisions by Gael (2026-11-11): tool named `strudel_mode`; samples in v1 so it works as on strudel.cc; the owner's "allow code" switch is on by default; **no sound safety on Strudel** (no loudness governor, no parameter clamps, no 0.9 cap, only the listener's volume); the code is shown collapsed with Copy code and a link to strudel.cc, and cannot be edited on sonorous; the hero page and the guide explain both engines; only `strudel_mode` switches engines (`set_sound` never does).

## Strudel in Self: no for now (2026-11-21, #128)
Self is the model's face and stays one voice: synth only, no `strudel_mode`. Quoting an earlier phrase is done with synth motifs (`set_sound` motif, with `name`, `recall` and `first`; mcp-tools.md, engine.md "Motif voice"), which work in every mode where the synth plays, Self included. While Strudel plays, a motif is ignored with a note.

## The tool
`strudel_mode { session_id?, on, code?, bpm?, colour?, final, title?, note? }` ([mcp-tools.md](mcp-tools.md)). `on: true` writes a state with `engine: "strudel"` and `pattern: { code, bpm }`; **all synth fields stay filled** (the paused synth), because `playingOf`, `hardCaps`, `nextGrid` and `silence` read them. `on: false` writes the synth back, silent and with no scene (v0.18.6): the picture goes to black and the next `set_sound` fades in from it. A change to Self (by the model) or an owner lock to Self writes or shows the synth again, and the player refuses to run a pattern unless the mode is Attuned or Jukebox and `allow_code` is true. The server parses the code with acorn (a syntax error comes back in the same result) and never runs it.

**Colour motion (v0.19.2).** Unless the model has set a `motion` in its sticky colour, the picture's motion follows the pattern's tempo, in `strudel_mode` on and in `set_sound` while Strudel plays (`applyPatternColour`): `bpm ≥ 110` pulse (`pulseHz` 0.3 when it had none), `≥ 80` drift, else breathe. Before, the motion stayed what the mood before the pattern had given (a calm mood's breathe under a 160 bpm pattern).

**The scene behind the drawings (v0.19.3, the owner's proposal).** A pattern state always carries a scene that goes with the music. It is never seen while the Strudel drawings show; it is what the listener sees, with its motion, when they turn "Strudel visuals" off (the view fades out over it). The model picks it with `colour.scene` in `strudel_mode` (sticky, like any colour). Without one, `patternScene(lastMood, bpm)` picks it: `moodToScene` on the last mood the model sent, stretched, with calm read from the tempo (the inverse of the mapping's tempo: `(150 − bpm) / 94`, clamped), its speed from `patternSceneMotion(bpm)`; marked `sceneAuto`, so the feedback does not report it as the model's. It takes the best-fitting scene even when it fits loosely (with the usual 0.3 threshold 45% of moods got none), and a mood that fits none at all gets one from the tempo (`motes` from 110 bpm, `seeds` from 80, else `tide`). So a pattern always has a scene of its own. v0.19.4: `playing.picture` names it, as `<scene> (picked for the music) density … speed …`; before, only a scene the model chose was reported. Turning the drawings back on over the scene is one crossfade: the view's black and its content come in together over 1.5 s (`IN_S`); before, the black came first over 0.6 s, a dip. v0.19.5: turning them off is the same crossfade the other way: the content and the black view fade out together over 1.5 s (`OUT_S`) while the scene comes up under them; before, the content went black in about 0.3 s and the black view then faded over 2 s. After Strudel (a pattern state, or the silent state `strudel_mode` off writes) the next synth state never glides from the paused synth's tempo (`tempoHeard`). `motion` is the legacy CSS pulse; the canvas scene shows the beat only with `sync: "beat"`, so a pattern at 110 bpm or more also gets `sync: "beat"` unless the model set a sync (below 110 the sync is left to the feel). Before, turning the drawings off showed the synth state's old scene with no beat.

**Changing code (v0.19.3).** When new code's drawings arrive (`VizStore.setSpecs` after `swap`, which bumps `swaps`), the view keeps its last frame of the old drawings and fades it out over the new ones in 0.5 s (`SWAP_S`, `strudel-view.tsx`). Before, they swapped at once.

## Where the code runs
```
model code -> [worker inside a sandboxed frame] -- haps --> page -- validate --> superdough -> listener volume -> speakers
```
- `public/strudel/frame.html`, served with a CSP (`next.config.ts`): `default-src 'none'; script-src 'self' 'unsafe-eval'; worker-src blob:; connect-src 'none'; sandbox allow-scripts`, embedded as `<iframe sandbox="allow-scripts">` with **no `allow-same-origin`**: an opaque origin, so no storage, cookies, IndexedDB or same-origin requests. `frame.ts` starts a blob worker from source the page sends and relays its messages with a per-load token the code cannot read, rate limited to 600 events a second.
- `strudel/worker.ts` (built to `public/strudel/worker.js` by `pnpm build:strudel`, part of `pnpm build`; run it after changing the worker) loads `@strudel/core`, `mini`, `tonal`, `transpiler`, evaluates the code with Strudel's own `repl`, and runs its own scheduler on the page's clock: it looks 300 ms ahead and posts events (haps), never sound. `Math.random` is seeded from the state's seed. Drawing methods (`pianoroll`, `scope`...) and `setcps` are no-ops that add a note to the report. `samples({...})` is refused; `samples('github:tidalcycles/dirt-samples')` asks the page.
- The page (`lib/strudel/output.ts`) checks each event's shape (`protocol.ts`: known key names, finite numbers, short strings, no limit on loudness or range), plays it with `superdough` into `AudioOutput.strudelBus` (the listener's volume and mute, like the synth's gain), loads samples from the allowed banks only (`banks.ts`, pinned commits), and has a watchdog: no heartbeat for 2.5 s (an endless loop) removes the frame and reports it.
- Checked in Chromium (2026-11-11): fetch, XHR, `importScripts` of another script, IndexedDB, storage, `parent`, a nested worker's fetch are all blocked; a `while(true)` freezes only the worker. A hostile run is in `scripts/strudel-sandbox/check.py`. Not checked: Safari (an opaque-origin blob worker needs a check on a Mac or iPhone).
- Honest limits: the code can burn CPU in its worker (hence the watchdog), can write any text into its own report (it is the model's code, so that is the model's own context), and nothing limits how loud or harsh it is.
- Findings of the first test (2026-11-11), and what the code does now:
  - **Level match on the synth side.** The synth was the faint one, so the fix raises it, not Strudel: `SYNTH_MAKEUP = 2.5` (about +8 dB) multiplies the listener's gain for the synth in `audio.ts`. Strudel is untouched. The state's own volume (cap 0.9) and the engine's soft limiter are unchanged. Measured in headless Chrome at the default slider: the synth peaked at 0.07 of full scale before, 0.18 now; a drums, bass and melody Strudel pattern peaks at about 0.5 and averages about the same as the synth now. Retune the constant if the two drift apart.
  - **Odd values.** An event with NaN or Infinity in it is dropped whole (the structural check). A huge finite value such as `.gain(1e9)` is passed to Web Audio as is and sonorous does not clamp it. What happens depends on the browser: in headless Chrome the graph carried values around 5e7, which the output clips to full scale (a loud, harsh note), while the tester heard silence on desktop Brave. Treat it as potentially painfully loud. A dropped event does not show in `get_feedback`: the report is the first one only, and `events_per_cycle` is counted in the worker, before the page's check.
  - **Restart.** A stop holds the pattern's fade node at zero (notes already handed to superdough, and their tails, sit upstream of it); the next play cuts them with a fresh node. So no note can sound at full volume after a fade (checked: no sound after the fade end in a headless run). The page drops events that are already more than 150 ms late (a throttled worker catching up used to play them in a burst), and the watchdog clock restarts with each play. Pressing Play within the fade of a Stop restarts the pattern (it used to be lost).
  - **Owner switches.** When the owner locks the mode to Self or turns code off, the database function (`stop_pattern`, migration 0029) strips `engine` and `pattern` from the playing state, keeping them in `intent.stopped_pattern`, so the synth state plays on every device, after a reload, and in `get_feedback`.   - **Reports.** Each play carries a sequence number that the worker echoes in its reports, so a late report from older code is not filed under the new code. Sending the same code again gets the stored report.

## How this relates to Strudel's "project start"
strudel.cc's [project-start page](https://strudel.cc/technical-manual/project-start/) offers three ways in: `@strudel/embed` (an iframe of the site), `@strudel/repl` (the `<strudel-editor>` web component) and `@strudel/web` (no UI, "build your own"). All three evaluate the code in the page. Sonorous takes the "build your own" road on purpose, and uses the same pieces Strudel's REPL is made of (`@strudel/core`'s `repl` and pattern engine, `mini`, `tonal`, `transpiler`, and `superdough` for sound), but splits them: the code is evaluated in a worker inside a sandboxed frame, and the page only plays the events and draws the pictures. That split is what keeps model-written code away from the account and the network. No Strudel code is patched.

## The picture
While Strudel plays and "Strudel visuals" is on (the default; a per-device setting next to "Allow Strudel", saved in `se:picture`), the scenes give way to Strudel's own picture (`components/player/strudel-view.tsx`): the model's code fills the background in the app's mono face (JetBrains Mono, as the rest of the data text), lit by the parts that sound, with the drawings the code asks for behind it. Turn the setting off and the scenes come back. A synth sound that takes over fades the view out; a silence fades it with the same level as the scenes (the visual canvas keeps running underneath, paints nothing, and hands its level and beat to the view, so the first-bar wait and the fades are the ones the scenes have).
- **Lighting the code.** Each event leaves the worker with `loc`, the spans of the code it came from (`hap.context.locations`: offsets into the code as the model wrote it, checked in the page as whole numbers inside the code). The page keeps them as marks and lights the spans whose event is on at the cycle the ear is at, with a short fade after (`litSpans`). Colour: the event's own `.color()` when it is a plain colour, else the hue of the model's colour field. The code goes in as text nodes, never markup.
- **Drawings.** The worker replaces Strudel's drawing methods (`pianoroll`, `punchcard`, `wordfall`, `spiral`, `pitchwheel`, `scope`, `tscope`, `fscope`, `spectrum`, each with its `_` form, and the function forms `all(pianoroll)`) with a recorder: it notes the name and the plain options, and tags the events of that pattern. It sends the specs (`viz`) and, on a channel of its own (`draw`, 2000 events a second, never to the speakers), the tagged events from some cycles behind to some cycles ahead of now. The page checks both (`validateViz`, `validateDrawHap`: known names, numbers, booleans, short plain strings, colours only as plain colours, never `url(` or `var(`) and draws them. `markcss` and `hydra` stay ignored with a note (Gael 2026-11-14: everything except custom CSS; `hydra` would run model-written shader code in the page, which the sandbox exists to prevent). Spiral and spectrum were dropped on 2026-11-14 and brought back the same day with pitchwheel: `markcss` would put model-written CSS into the page.
- **What is Strudel's own code.** The pianoroll family is `__pianoroll` and the pitch wheel is `pitchwheel`, both from `@strudel/draw`, used unmodified in a canvas we give them (the wheel takes the session's colour through Strudel's own `setTheme`). The spiral and the scopes are written after Strudel's `spiral.mjs`, `scope.mjs` and `spectrum.mjs` (same geometry and options) because those read Strudel's own Hap objects and superdough's analysers; the spiral cuts each event to the two cycles it shows and draws at most 400 events of at most 240 pieces, fills each square-ended band as one shape on the radius through its ends (a stroked band is cut square to its chord and leaves a wedge between neighbours), limits `stretch` to 0.25 to 2.5 and never draws a band thicker than the gap between two turns (so a huge `stretch` still shows a spiral); `lib/strudel/draw.ts` says so in its header. The scopes read an `AnalyserNode` on the pattern's output, after its fade and before the listener's volume. Folded rows (the default of the roll, punchcard and wordfall) are one per value in the window, so Strudel's own code moves every bar as notes come and go; `Painter` remembers the rows each lane has seen (up to 128, cleared on a new code) and hands `__pianoroll` one ghost event per missing row, far off in time (it draws nothing, only keeps the row), so the rows stay put and a row with no notes stays empty (not done with `fold: 0`, `autorange`, `minMidi` or `maxMidi`). Plain calls (`.pianoroll()`) fill the view behind the code; `_` calls share a band along the bottom, one lane each. With no drawing call the view is the code and its lighting only (Gael, 2026-11-14).

The scene canvas keeps painting the scenes under the view until the view is opaque, so a switch to or from the scenes is a cross-fade (about 0.4 s in, 0.3 s out); coming from nothing the view is there at once. ## Time and tempo
`bpm` is authoritative (`setcps` is ignored); one cycle is one bar of four beats, `cps = bpm / 240`. The cycle position comes from the shared timeline (`beatsAt(state, tau) / 4`, with `grid.beat` carried through engine switches), so devices hear the same bar. A pattern starts on the **next bar**; there is **no tempo glide** (`beatsAt` and `tempoAt` return `pattern.bpm` for a Strudel state), so the picture follows the music. Events are scheduled `latency` early, as the picture is drawn `latency` late.

## What the model learns
No `reads_as` or spectrogram (Strudel renders only in a browser). The owner's player reports what the code did through `report_pattern` (error text, events per cycle, sounds used, shimmed calls), once per state, and only the session owner can write it: a link listener must not put text into the model's context. It returns as `pattern` in `strudel_mode`, `get_feedback` and the next call, labelled `source: "the owner's player"`; with nobody listening it says it has not run.

## Listener side
Collapsed "Strudel code" panel in the player: read-only code, **Copy code** (adds `setcps(bpm/60/4)` when the code has no tempo, so it sounds the same there), **Open in Strudel** (strudel.cc with the code in the URL hash: base64, URL-encoded). The owner has "Let the model play Strudel code" in the player. The panel is a `details` with the usual marker, under the Mode block (for the owner) and two half-width buttons; it carries no licence text (the guide says the code is the model's).
