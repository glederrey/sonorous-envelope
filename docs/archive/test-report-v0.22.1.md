## Feedback for Claude Code

1. **Late first snapshot with Strudel (test 7).** What happened: after `strudel_mode` on, `inspect` snapshot kept returning the last synth image (`turn 14 · synth`, `age_s` 135, then 150) for at least 45 s. The owner's "What the AI can see" showed the same image. The first Strudel snapshot arrived about 3 min after the start. Expected: a snapshot 8 to 14 s after the new sound (here, the pattern start), then every 30 s. Later periodic snapshots did arrive about every 30 s. The first capture after a switch from the synth to Strudel seems to be missed, perhaps because it waits for a synth state that never comes. Error text returned: `"of": "an earlier sound: the current one is newer, ask again in about 10 s"`.
2. **Press line lingers (test 4).** What happened: after the model's answer arrives, the line keeps showing which button was pressed for a couple of seconds. Expected: it clears, or moves to the next state, as soon as the update lands.
3. **"model" vs "AI" wording, all pages and components (Gael's request).** The control panel still says "The model may offer another mode, and switches only after you say yes.", "The model may play live code…", "The model reads this as soon as it listens (Live tuning), or on its next message…" and "What the model set". Next to these are "Tell the AI what you heard" and "What the AI can see". Please do a pass on every page and component so the listener always reads "AI", not "model".
4. **Scrollbar style.** The scrollbar now stays inside the rounded corners on desktop and phone. On desktop it still shows the default up/down arrow buttons and a grey track. Gael would like a nicer style (thin, no arrows, matching the panel).
5. **Text before `listen` is hidden in claude.ai.** What happened: with Live tuning on, the rules make `listen` the last call of every message, so any question written before it counts as text between tool calls. claude.ai collapses that text, and Gael did not see three questions ("Which questions?"). Expected: the listener can read what the model asks. Suggestion: the Live tuning rule (or the `listen` result on `idle`) could tell the model to repeat any open question after `listen` returns, in its final text. The model worked around it by repeating questions after the call and by sending them verbatim before it.
6. **Big step on More of this (test 5).** More of this after a Faster step took the tempo from 78 to 119 bpm (gliding over 8 s), and the rate jumped from 1/4 to 1/16 in one step, with the drone turned off. Gael heard it as the right direction. A rate switch while the tempo glides is still a single jump (as noted in v0.19.5), so it may be worth gliding it or stepping through 1/8.
7. **Outside the brief: roughness on calm consonant sounds (same as v0.22.0 item 12).** `sound.roughness` read 0.72 (turn 1) and 0.81 (turns 4–5) for calm F# lydian states with no tension, rate 1/4 and the drone on. It read 0.31 for the lively 1/16 state with no drone, and 0.41 at 1/8 with the drone. The drone plus a sparse arp still seems to count as rough.
8. **Worked: `listen` carries `heard` too.** A Blaming press during a wait came back in `listen` as `{"event":"reactions","heard":[...]}`, which matches the panel text ("The model reads this as soon as it listens"). A short line in the `listen` description saying it returns `heard` as well as `reactions` would make that explicit.
