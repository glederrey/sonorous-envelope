## Feedback for Claude Code

1. **Softer/calmer apply one call late (tests 2 and 2b).** What happened: the `set_sound` that reads the press (the press shows in its own `reactions`) is not lowered or held; the rule only fires on the call after. With softer: turn 6 stayed at −28 dB (volume 0.45 → 0.5), and turn 7 (a plain hold) got `level lowered … 2 dB below your last`. With calmer: turn 8 went −30 → −28 dB (volume 0.35 → 0.5) with no `clamped`, so the answer to "calmer" got louder. Expected: when the press is first read in this same call's result (no `listen` in between, which is the normal path without live tuning), this call is already lowered by 2 dB (softer) or held (calmer). Probably the check looks only at presses marked read *before* this call; it should also count presses this call marks read.
2. **Server loses track of Strudel after Allow Strudel off → on (test 1).** What happened: the player brought the same pattern back, in time (Gael: yes), but the server state still said Strudel was stopped, with the note `the owner stopped your Strudel pattern when they changed the mode; …` (Gael did not change the mode, only toggled Allow Strudel). The synth state was `volume: 0`. The next `set_sound` then switched the engine back to the synth and played it (Gael heard "the synth, soft arp", waves on screen, no code), although the rules say `set_sound cannot switch the engine; while Strudel is on it only sets the picture`. Expected: after the player resumes the pattern, the server marks Strudel as playing again (no "stopped" note), and the next `set_sound` only sets the picture. The note's wording ("when they changed the mode") is also wrong for this case.
3. **Unrounded tempo in the one-call note (test 3).** `arp.tempo 120 to 59.58`, while `playing.tempo` and `tempo 120 to 60` say 60. Suggest rounding to match.
4. **Minor, outside the brief: repeated turn numbers.** A non-final `set_sound` and the final one after it in the same message both returned `turn: 9`, and the Jukebox switch and the `strudel_mode` after it both returned `turn: 2`. Fine if turns count messages, not calls; worth saying so in the docs, since `inspect history` lists "states".
5. **Brief wording for test 3.** To let the listener hear the one-call tempo, the brief could say to wait for an answer (or ~10 s) between the two calls; sent back to back, the 4 s glide up is cut short and nothing is heard.
